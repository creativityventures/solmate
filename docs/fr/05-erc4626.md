# Chapitre 5 — ERC4626 : l interface commune des vaults tokenises

`ERC4626.sol` implemente le standard ERC-4626, une interface commune pour les "vaults" qui acceptent un depot d'un actif ERC20 (`asset`) et emettent en echange des parts elles-memes ERC20 (le contrat herite d'`ERC20`, chapitre 2) representant une quote-part du vault. C'est exactement le motif deja rencontre dans plusieurs parcours de ce compte et d'autres comptes de la bibliotheque (aToken d'Aave, rETH de Rocket Pool, parts de pool Balancer) : Solmate en fournit ici une implementation de reference minimale et generique, plutot qu'une implementation liee a un protocole precis.

Le contrat ne definit qu'une seule fonction abstraite que chaque vault derive doit implementer : `totalAssets()`, la valeur totale geree par le vault dans l'unite de l'actif sous-jacent. Toutes les conversions (`convertToShares`, `convertToAssets`) et operations (`deposit`, `mint`, `withdraw`, `redeem`) se deduisent automatiquement de cette seule fonction et de l'offre totale de parts courante (`totalSupply`, heritee d'`ERC20`).

`convertToShares` traite le cas particulier d'un vault vide (`totalSupply == 0`) en retournant les actifs tels quels comme nombre de parts, evitant une division par zero et fixant le taux de change initial a 1:1 pour le tout premier deposant.
